1. Objetivo y alcance

El sistema permite recoger piezas físicas, instalarlas en soportes compatibles del avión y volver a desmontarlas.

Se ha planteado como una base reutilizable: el mismo patrón de piezas, soportes y controlador podrá aplicarse en el futuro a otros vehículos o máquinas.

Funcionalidades contempladas

  • Detectar puntos de montaje delante de la cámara del jugador.
  • Comprobar la compatibilidad entre el tipo de pieza y el soporte.
  • Previsualizar el encaje de la pieza.
  • Alinear la pieza con la posición y orientación del anclaje.
  • Integrar la pieza en la jerarquía y física del avión.
  • Desmontarla y devolverla al contenedor de piezas sueltas.
  • Guardar y restaurar propiedades físicas de cada pieza.
Alcance de esta versión: esta documentación describe el sistema de montaje que ya funciona. No incluye todavía tren de aterrizaje, suspensión, despegue, vuelo, aterrizaje ni ajuste automático de altura.

2.1 AvionBase

Es la raíz del vehículo. Contiene la estructura fija, los puntos de montaje y el contenedor de piezas instaladas. También tiene el Rigidbody principal del avión.

Configuración registrada:

Propiedad del RigidbodyValor
Mass100
Use GravityDesactivado
Is KinematicActivado
InterpolateActivado
Collision DetectionContinuous

Esta configuración corresponde a la fase de montaje. No debe considerarse todavía la configuración definitiva para volar.

2.2 PiezasSueltas

Es un contenedor independiente de AvionBase. Sus piezas no forman parte del avión: cada una conserva su propio Rigidbody y puede moverse y colisionar por separado.

2.3 PiezasMontadas

Es hijo de AvionBase. Cuando una pieza se instala, pasa a ser hija de este contenedor y su collider queda asociado al Rigidbody principal del avión al eliminarse el Rigidbody individual.

Mantener PiezasSueltas fuera de AvionBase evita que una pieza que todavía no se ha instalado se mueva como parte del avión.

Cada soporte está dentro de AvionBase/PuntosMontaje y dispone de un BoxCollider con Is Trigger activado y del componente PuntoMontaje.

3.1 ¿Por qué un BoxCollider Trigger?

El collider define una zona de detección, no una superficie que deba bloquear físicamente la pieza. El código consulta esos triggers mediante un SphereCast con QueryTriggerInteraction.Collide.

3.2 El anclaje

El campo opcional anclaje es el Transform que define la posición y orientación final de la pieza. Si no se asigna, se utiliza el Transform del propio soporte.

En una pieza, el campo opcional puntoDeEncaje define qué punto de la pieza debe coincidir con el anclaje del soporte. Si no se asigna, se utiliza el Transform raíz de la pieza.

4. Capas y matriz de colisiones

CapaUso previsto
DefaultPiezas sueltas y objetos generales; el suelo está en esta capa según la configuración descrita.
AvionEstructura fija del avión.
MontajeColliders Trigger de los puntos de montaje.
PiezasMontadasPiezas instaladas en el avión.

4.1 Matriz de colisiones relevante

  • PiezasMontadas ↔ Avion: desactivada para evitar que las piezas instaladas empujen o interfieran con la estructura fija.
  • PiezasMontadas ↔ Default: activada para permitir colisiones con el suelo y otros objetos de esa capa.
  • PiezasMontadas ↔ Montaje: debe permanecer habilitada según la configuración restaurada para que no se pierda la detección necesaria de los soportes.
Cuando se cambia la capa de un objeto padre desde Unity, puede aplicarse también a sus hijos. Después de asignar Avion a la estructura, hay que comprobar que los puntos de montaje sigan en Montaje.

El campo capasPuntosMontaje de SistemaMontaje debe incluir la capa Montaje.

5. Script PiezaModular.cs

Este componente identifica la clase de pieza, define su punto de encaje opcional y registra si está instalada.

using UnityEngine;

public enum TipoPieza
{
    Motor,
    Helice,
    Ruedas,
    Alas,
    Mandos
}

public class PiezaModular : MonoBehaviour
{
    [Header("Identificación")]
    public TipoPieza tipo;

    [Header("Encaje")]
    public Transform puntoDeEncaje;

    [Header("Estado")]
    public bool estaInstalada = false;
}

5.1 TipoPieza y tipo

TipoPieza enumera las categorías permitidas. El campo tipo se configura en cada pieza desde el Inspector.

ObjetoValor de tipo
MotorVisualMotor
HeliceHelice
RuedaIzq y RuedaDerRuedas
AlaIzquierda y AlaDerechaAlas
MandosMandos

5.2 puntoDeEncaje

Es opcional. Permite que el punto de referencia para alinear la pieza sea distinto de su pivote raíz. Si queda vacío, se utiliza pieza.transform.

5.3 estaInstalada

Es un indicador booleano. Se pone a true al registrar el montaje y vuelve a false al liberar el soporte.

6. Script PuntoMontaje.cs

Este componente representa un soporte individual. Sabe qué tipo acepta y qué pieza tiene instalada.

using UnityEngine;

public class PuntoMontaje : MonoBehaviour
{
    [Header("Configuracion")]
    public TipoPieza tipoAceptado;

    [Header("Punto de encaje")]
    public Transform anclaje;

    [Header("Estado")]
    public PiezaModular piezaInstalada;

    public bool Ocupado
    {
        get { return piezaInstalada != null; }
    }

    public bool PuedeAceptar(PiezaModular pieza)
    {
        if (pieza == null)
            return false;

        if (Ocupado)
            return false;

        return pieza.tipo == tipoAceptado;
    }

    public void RegistrarPieza(PiezaModular pieza)
    {
        if (!PuedeAceptar(pieza))
            return;

        piezaInstalada = pieza;
        pieza.estaInstalada = true;
    }

    public void LiberarPunto()
    {
        if (piezaInstalada == null)
            return;

        piezaInstalada.estaInstalada = false;
        piezaInstalada = null;
    }
}

6.1 Ocupado

Indica si el soporte ya tiene una pieza. Se considera ocupado cuando piezaInstalada no es null.

6.2 PuedeAceptar

Comprueba tres condiciones: que la pieza exista, que el soporte esté libre y que el tipo de pieza coincida con tipoAceptado.

6.3 RegistrarPieza

Si la pieza es válida, guarda su referencia y marca estaInstalada como verdadero.

6.4 LiberarPunto

Marca la pieza como no instalada y limpia la referencia del soporte.

Nota de integración: en la versión de SistemaMontaje que el usuario indicó que compila, la comprobación de desmontaje utiliza punto.ocupado en minúsculas. El código de referencia anterior muestra una propiedad llamada Ocupado. C# distingue mayúsculas y minúsculas: ambos scripts deben utilizar exactamente el mismo nombre. No cambiarlo sin comprobar el código real del proyecto.

7. Script SistemaMontaje.cs

Es el controlador central. Detecta soportes, realiza el montaje, desmonta piezas y gestiona la física individual de cada una.

7.1 Referencias y parámetros

  • camaraJugador: cámara desde la que se lanza la detección.
  • distanciaDeInteraccion: distancia máxima de detección, configurada inicialmente en 4 unidades.
  • capasPuntosMontaje: máscara de capas que limita la detección a los soportes.
  • radioDeteccionMontaje: radio del SphereCast, inicialmente 0.4 unidades.
  • contenedorPiezasSueltas: Transform de PiezasSueltas.
  • contenedorPiezasMontadas: Transform de AvionBase/PiezasMontadas.
  • rigidbodyAvion: Rigidbody de AvionBase.

7.2 DatosFisicos

Es una clase interna que almacena los parámetros del Rigidbody original de cada pieza antes de instalarla:

  • Masa.
  • Linear Damping y Angular Damping.
  • Uso de gravedad.
  • Estado cinemático.
  • Detección de colisiones.
  • Restricciones.
  • Modo de detección de colisiones.
  • Interpolación.

Un diccionario relaciona cada PiezaModular con sus datos físicos. Así se pueden recuperar cuando se desmonta.

7.3 DetectarPuntoMontaje

Desde el centro de la cámara se genera un rayo. En lugar de un Raycast de grosor cero, se utiliza un SphereCast con radio configurable. Esto hace más fácil apuntar a colliders de montaje estrechos.

La consulta:

  • Parte del centro de la vista (ViewportPointToRay(0.5, 0.5)).
  • Recorre hasta distanciaDeInteraccion.
  • Solo consulta las capas incluidas en capasPuntosMontaje.
  • Incluye colliders Trigger.
  • Busca el componente PuntoMontaje en el collider o en sus padres.

7.4 ObtenerPuntoMontaje

Es un método público que devuelve el punto detectado. Permite que otros scripts consulten qué soporte está bajo la mira.

7.5 IntentarMontar

Recibe un Rigidbody de una pieza y un punto de montaje. El procedimiento es:

  1. Comprueba que ambas referencias existen.
  2. Comprueba que están asignados el Rigidbody del avión y el contenedor de piezas montadas.
  3. Obtiene PiezaModular desde el mismo objeto que contiene el Rigidbody.
  4. Comprueba que el soporte acepta esa pieza.
  5. Elige el punto de encaje de la pieza y el anclaje del soporte. Si no existen, utiliza los Transform raíz correspondientes.
  6. Calcula la diferencia de rotación necesaria para hacer coincidir las orientaciones.
  7. Guarda los parámetros físicos originales del Rigidbody.
  8. Detiene las velocidades lineal y angular si el Rigidbody no es cinemático.
  9. Lo convierte en cinemático y desactiva la gravedad.
  10. Aplica la rotación y corrige la posición para hacer coincidir el punto de encaje con el anclaje.
  11. Convierte la pieza en hija de PiezasMontadas.
  12. Asigna recursivamente la capa PiezasMontadas.
  13. Registra la pieza en el soporte.
  14. Destruye el Rigidbody individual.

Al eliminar el Rigidbody individual, los colliders de la pieza pasan a formar parte del conjunto físico asociado al Rigidbody del avión, al estar la pieza dentro de su jerarquía.

7.6 IntentarDesmontar

Este método detecta el soporte que está bajo la mira y comprueba que esté ocupado.

  1. Obtiene la pieza registrada en el soporte.
  2. Comprueba que existe el contenedor de piezas sueltas.
  3. Busca los datos físicos que se guardaron durante el montaje.
  4. Libera el punto de montaje.
  5. Devuelve la pieza a PiezasSueltas, conservando su posición mundial.
  6. Asigna recursivamente la capa Default.
  7. Añade un Rigidbody nuevo al objeto raíz.
  8. Restaura los parámetros físicos guardados.
  9. Reinicia las velocidades si el nuevo Rigidbody no es cinemático.
  10. Elimina la entrada del diccionario.

7.7 PrevisualizarMontaje

Comprueba que la pieza puede entrar en el soporte y aplica la misma alineación de rotación y posición que utiliza el montaje definitivo. Devuelve true si puede realizar la operación.

Este método mueve la pieza real; no crea por sí solo una copia fantasma o un material translúcido. El comportamiento visual de la previsualización depende de cómo lo invoque el script que gestiona la interacción.

7.8 AsignarCapaRecursiva

Cambia la capa del objeto raíz y de todos sus hijos. Si el número de capa es inválido, muestra un error en la consola.

9. Configuración del Inspector

9.1 En cada pieza suelta

  • El objeto raíz tiene un Collider.
  • El objeto raíz tiene un Rigidbody.
  • El objeto raíz tiene PiezaModular.
  • El tag utilizado para identificar piezas recogibles es Interactuable.
  • El campo tipo coincide con la pieza.
  • puntoDeEncaje puede quedar vacío si se utiliza el pivote raíz.

9.2 En cada punto de montaje

  • Contiene un BoxCollider con Is Trigger activado.
  • Está en la capa Montaje.
  • Contiene el componente PuntoMontaje.
  • tipoAceptado coincide con la pieza prevista.
  • anclaje es opcional.
  • piezaInstalada comienza vacío.

10. Decisiones físicas y funcionamiento de Rigidbody

10.1 Mientras una pieza está suelta

La pieza tiene su Rigidbody individual. Sus propiedades determinan cómo cae, se mueve y colisiona.

10.2 Mientras está montada

La pieza se vuelve hija de PiezasMontadas, se le elimina el Rigidbody individual y sus colliders pasan a formar parte del Rigidbody raíz del avión. La capa cambia a PiezasMontadas.

10.3 Al desmontarla

Se añade un Rigidbody nuevo y se restauran los parámetros almacenados. El objeto vuelve al contenedor de piezas sueltas y a la capa Default.

Detalle técnico: Unity ejecuta Destroy(rb) al final del frame. Por tanto, la eliminación del Rigidbody no es instantánea en la misma línea de código. La implementación actual funciona en las pruebas descritas, pero conviene tener presente este detalle si en el futuro aparece un problema de física durante el frame del montaje.

El diccionario de datos físicos existe en memoria durante la ejecución. No guarda esos valores en disco ni permite reconstruirlos automáticamente después de cerrar y volver a abrir el juego.

11. Estado actual y límites conocidos

  • El sistema de montaje y desmontaje se considera funcional según las pruebas del proyecto.
  • La previsualización alinea la pieza real; no implementa por sí misma una malla fantasma.
  • El sistema no calcula todavía la altura del avión respecto al suelo.
  • No hay todavía tren de aterrizaje funcional ni suspensión.
  • No hay todavía lógica de despegue, vuelo o aterrizaje.
  • El Rigidbody principal está configurado como cinemático y sin gravedad; esto tendrá que cambiar o adaptarse para el vuelo.
  • La compatibilidad se basa en el enum TipoPieza; todavía no existe un sistema de requisitos por vehículo ni dependencias entre componentes.
  • La recogida mediante F depende de otro controlador que no está incluido en los tres scripts documentados.

Precaución al ampliar el sistema

La versión actual es la base funcional. Antes de modificarla, conviene conservar una copia de los scripts y probar cada cambio por separado. No se deben cambiar simultáneamente las capas, la jerarquía y la lógica física, porque sería difícil identificar la causa de una regresión.

12. Lista de comprobación para validar la escena

  • ☐ AvionBase tiene un único Rigidbody principal.
  • ☐ Las piezas estructurales fijas no tienen Rigidbodies individuales adicionales.
  • ☐ PiezasMontadas es hijo de AvionBase.
  • ☐ PiezasSueltas está fuera de AvionBase.
  • ☐ Cada pieza suelta tiene Rigidbody, Collider y PiezaModular en el objeto raíz.
  • ☐ Cada soporte tiene BoxCollider Trigger y PuntoMontaje.
  • ☐ Los soportes están en la capa Montaje.
  • ☐ La máscara capasPuntosMontaje incluye Montaje.
  • ☐ Los tipos de piezas y soportes coinciden.
  • ☐ Las referencias del Inspector de SistemaMontaje están asignadas.
  • ☐ La matriz de colisiones conserva las relaciones descritas.
  • ☐ Se prueba montar una pieza compatible.
  • ☐ Se prueba que una pieza incompatible no se monte.
  • ☐ Se prueba que un soporte ocupado no acepte otra pieza.
  • ☐ Se prueba desmontar y comprobar que la pieza recupera su física.

13. Próximas fases del proyecto

Estas funciones todavía no están implementadas. Se enumeran para dejar claro cómo evolucionará el proyecto sin confundirlas con el estado actual.

  1. Tren de aterrizaje: definir puntos de contacto con el suelo y el comportamiento cuando falten ruedas.
  2. Altura en tierra: ajustar la posición inicial del avión para que las ruedas apoyen correctamente, sin imponer ese ajuste durante el vuelo.
  3. Física de vuelo: revisar el Rigidbody principal, gravedad, fuerzas, torque y controles.
  4. Despegue y aterrizaje: permitir que el avión abandone el suelo y vuelva a contactar con él mediante física.
  5. Requisitos de componentes: impedir o limitar funciones cuando falten motor, hélice, alas, mandos o ruedas.
  6. Generalización: separar configuración del vehículo y tipos de soportes para reutilizar el sistema en otras máquinas.
Principio de desarrollo: mantener intacto el montaje que ya funciona y añadir cada sistema nuevo de forma independiente, con pruebas pequeñas después de cada modificación.
