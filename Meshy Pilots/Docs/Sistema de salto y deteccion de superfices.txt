Implementado y funcionando
1. Objetivo del sistema
Hemos rediseñado la detección del suelo para que el jugador pueda saltar sobre distintas superficies sin depender de un Raycast demasiado estrecho.

El comportamiento que buscamos es:
Superficie	¿Permite saltar?
Suelo normal	Sí
Plataformas (Structure)	Sí
Objetos normales	Sí
Objetos interactuables	No
Mientras está en el aire	No

2. Cambios realizados
A. Sustitución de Raycast por SphereCast
Problema original: utilizábamos un Raycast, que lanzaba una línea recta desde los pies del jugador.

Esto provocaba que, si el punto de detección no coincidía exactamente con el centro de una plataforma, no detectase la superficie.

Solución: utilizamos Physics.SphereCast().
Physics.SphereCast(
    origen,
    groundRadius,
    Vector3.down,
    out RaycastHit hit,
    groundDistance,
    groundLayer,
    QueryTriggerInteraction.Ignore
);


La diferencia es que ahora Unity utiliza una esfera invisible para detectar las superficies.









B. Sistema de capas
Configuramos Ground Layer para reconocer las superficies válidas.
- Suelo: permite detectar el terreno.
- Structure: permite detectar las plataformas.
Durante las pruebas también quitamos temporalmente el filtro de capas mediante ~0 para comprobar si el problema estaba en la LayerMask.

~0 representa todas las capas.
C. Identificación de objetos interactuables
Añadimos una comprobación del tag Interactuable.
Transform objeto = hit.collider.transform;
bool esInteractuable = false;

while (objeto != null)
{
    if (objeto.CompareTag("Interactuable"))
    {
        esInteractuable = true;
        break;
    }

    objeto = objeto.parent;
}

puedeSaltar = !esInteractuable;


Esto permite comprobar también los objetos padre cuando el collider está en un objeto hijo.

Así evitamos que el jugador pueda saltar desde objetos que forman parte del sistema de interacción.
D. Separación entre Update y FixedUpdate
Separamos las responsabilidades:
- Update(): comprueba la entrada del teclado y solicita el salto.
- FixedUpdate(): ejecuta las operaciones físicas del Rigidbody.
Utilizamos una variable llamada saltoSolicitado para comunicar ambos métodos.

Esto ayuda a gestionar correctamente el salto y la física.
3. Variables principales
Variable	Función
jumpForce	Fuerza del salto
groundCheck	Posición desde la que se detecta el suelo
groundRadius	Radio de la esfera de detección
groundDistance	Distancia de detección
groundLayer	Capas que pueden detectarse
puedeSaltar	Indica si el salto está permitido
saltoSolicitado	Guarda la solicitud de salto

4. Problemas encontrados y soluciones
Problema	Solución
El Raycast no detectaba bien los bordes	Sustituirlo por SphereCast
Detectaba el suelo demasiado arriba	Ajustar el origen y la distancia
Permitía saltos repetidos	Controlar cuándo se permite saltar
No detectaba las plataformas	Revisar las capas y probar sin filtro
Los objetos interactuables permitían saltar	Comprobar el tag en el objeto y sus padres
La detección y el salto daban resultados diferentes	Separar detección y ejecución física

5. Conceptos de Unity aprendidos
Con este sistema hemos trabajado varios conceptos importantes:
- Rigidbody: controla el movimiento físico del personaje.
- SphereCast: detecta superficies mediante un volumen esférico.
- LayerMask: permite filtrar qué capas detecta una consulta física.
- Tags: identifican tipos de objetos.
- Transform.parent: permite recorrer la jerarquía de objetos.
- Update y FixedUpdate: separan la entrada del usuario de la simulación física.

6. Resultado final
El sistema permite detectar superficies con un área más amplia que el Raycast original, identificar objetos interactuables y controlar cuándo se puede saltar.
