1. Visión general

El sistema permite que el jugador mire un objeto compatible, lo recoja con F, lo transporte mediante una fuerza de atracción hacia un punto situado delante de la cámara y lo instale en un punto de montaje con G. Una vez instalada, la pieza queda acoplada a la estructura y deja de responder a la gravedad. Para desmontarla, el jugador debe entrar en un segundo volumen Trigger, destinado específicamente a autorizar el desmontaje, y pulsar G.

DetectarRaycast identifica una pieza que el jugador mira.
RecogerF asigna su Rigidbody a objetoAgarrado.
TransportarFixedUpdate mueve el Rigidbody hacia puntoDeSujecion.
MontarG coloca la pieza en el anclaje y la hace cinemática.
Autorizar desmontajeEl jugador entra en el Trigger de desmontaje.
DesmontarG separa la pieza y reactiva gravedad y física.
Idea principal: hay dos Triggers con funciones distintas. El Trigger de PuntoMontaje1 detecta una pieza que se puede instalar. El Trigger de TriggerDesmontajePieza detecta al jugador y permite desmontar una pieza ya instalada.

2. Arquitectura y jerarquía

Los cuatro scripts colaboran, pero cada uno tiene una responsabilidad concreta:

ScriptResponsabilidadQuién lo consulta
TriggerDesmontajePiezaRegistra si el jugador está dentro del área autorizada para desmontar.PuntoMontaje1 y SistemaInteraccion.
PuntoMontaje1Detecta piezas compatibles, las instala y las desmonta al recibir G.SistemaInteraccion consulta sus estados.
SistemaInteraccionGestiona el Raycast, la recogida, el transporte, la suelta y los textos de ayuda.Recibe referencias a cámara y punto de montaje.

Una jerarquía típica puede ser:

Escena
├── Estructura
│   └── PuntoMontaje1 (Collider con Is Trigger)
│       └── PuntoAnclaje (Transform)
├── ZonaDesmontaje
│   ├── Collider con Is Trigger
│   └── TriggerDesmontajePieza
├── Player
│   ├── SistemaInteraccion
│   ├── PlayerTrigger
│   └── Cámara del jugador (o referencia a Main Camera)
└── Esfera / Pieza
    ├── Rigidbody
    ├── Collider
    └── PiezaMontaje1
La jerarquía es orientativa. Los componentes pueden estar distribuidos de otra manera. Lo importante es que las referencias estén asignadas correctamente y que los colliders y rigidbodies permitan que Unity genere los eventos Trigger.

3. Script 1 — TriggerDesmontajePieza

using UnityEngine;

public class TriggerDesmontajePieza : MonoBehaviour
{
    public bool playerInRangePoint1 = false;
    public PlayerTrigger playerTrigger;

    private void OnTriggerEnter(Collider other)
    {
        PlayerTrigger jugador = other.GetComponentInParent<PlayerTrigger>();

        if (jugador == null)
            return;

        playerTrigger = jugador;
        playerInRangePoint1 = true;
    }

    private void OnTriggerExit(Collider other)
    {
        PlayerTrigger jugador = other.GetComponentInParent<PlayerTrigger>();

        if (jugador == null)
            return;

        playerInRangePoint1 = false;
        playerTrigger = null;
    }
}

3.1. ¿Para qué sirve?

Este componente se coloca en el objeto que representa la zona donde el jugador puede desmontar una pieza. No instala ni desmonta nada por sí mismo. Su única tarea es comunicar si el jugador está dentro o fuera de esa zona.

3.2. Variables

VariableTipoFunción
playerInRangePoint1boolVale false inicialmente. Pasa a true cuando entra un collider perteneciente al jugador y vuelve a false cuando sale.
playerTriggerPlayerTriggerGuarda la referencia al componente PlayerTrigger encontrado en el collider que entra. Puede servir para identificar al jugador desde otros scripts.

3.3. OnTriggerEnter(Collider other)

Unity llama a este método cuando otro collider entra en el volumen Trigger.

  1. other es el collider que acaba de entrar, no necesariamente el objeto raíz del jugador.
  2. GetComponentInParent<PlayerTrigger>() busca el componente en el propio objeto del collider y después en sus padres. Esto permite que el collider esté en un objeto hijo del jugador.
  3. Si no encuentra PlayerTrigger, jugador será null y el método termina con return. Así no se considera jugador a una pieza u otro objeto cualquiera.
  4. Si lo encuentra, guarda la referencia y establece playerInRangePoint1 = true.

3.4. OnTriggerExit(Collider other)

Unity llama a este método cuando un collider sale del volumen. Se repite la búsqueda de PlayerTrigger. Si no pertenece al jugador, se ignora. Si pertenece, se pone el indicador a false y se limpia la referencia.

Limitación importante del código actual: si el jugador tiene varios colliders, uno puede salir mientras otro continúa dentro. Este script pondrá el indicador a false al salir cualquiera de ellos que tenga PlayerTrigger. En ese caso se necesita contar los colliders del jugador que siguen dentro, en vez de usar un único evento de salida como señal definitiva.

3.5. Requisitos de configuración

  • El objeto de la zona debe tener un Collider con Is Trigger activado.
  • El jugador debe tener un collider que entre en la zona.
  • El objeto del jugador o uno de sus padres debe tener el componente PlayerTrigger.
  • La configuración de Rigidbody/CharacterController debe permitir que Unity genere los eventos Trigger. Las reglas dependen de los tipos de collider y cuerpo físico usados.

4. Script 2 — PuntoMontaje1

using Unity.VisualScripting;
using UnityEngine;

public class PuntoMontaje1 : MonoBehaviour
{
    public Transform puntoAnclaje;
    public PiezaMontaje1 piezaDetectada;
    public PiezaMontaje1 piezaInstalada;
    public bool inTrigger;

    public SistemaInteraccion sistemaInteraccion;
    public TriggerDesmontajePieza triggerDesmontajePieza;

    private void OnTriggerEnter(Collider other)
    {
        PiezaMontaje1 piezaMontaje1 =
            other.GetComponentInParent<PiezaMontaje1>();

        if (piezaMontaje1 == null)
            return;

        if (piezaMontaje1.estaMontada)
            return;

        piezaDetectada = piezaMontaje1;
        inTrigger = true;
    }

    private void OnTriggerExit(Collider other)
    {
        PiezaMontaje1 pieza =
            other.GetComponentInParent<PiezaMontaje1>();

        if (pieza == null || pieza.estaMontada)
            return;

        if (piezaDetectada == pieza)
        {
            piezaDetectada = null;
            inTrigger = false;
        }
    }

    void Start()
    {
        sistemaInteraccion =
            sistemaInteraccion.GetComponent<SistemaInteraccion>();

        triggerDesmontajePieza =
            triggerDesmontajePieza.GetComponent<TriggerDesmontajePieza>();
    }

    void Update()
    {
        if (!Input.GetKeyDown(KeyCode.G))
            return;

        if (piezaInstalada != null)
            DesmontarPieza();

        if (piezaDetectada != null)
        {
            MontarPieza();
            sistemaInteraccion.SoltarObjeto();
        }
    }

    public void MontarPieza()
    {
        if (puntoAnclaje == null)
            return;

        PiezaMontaje1 piezaMontaje1 = piezaDetectada;
        Rigidbody rb =
            piezaDetectada.GetComponentInParent<Rigidbody>();

        piezaMontaje1.transform.SetPositionAndRotation(
            puntoAnclaje.position, puntoAnclaje.rotation);

        if (rb != null)
        {
            rb.linearVelocity = Vector3.zero;
            rb.angularVelocity = Vector3.zero;
            rb.isKinematic = true;
            rb.useGravity = false;
        }

        piezaMontaje1.transform.SetParent(transform, true);
        piezaMontaje1.estaMontada = true;
        piezaInstalada = piezaMontaje1;
        piezaDetectada = null;
    }

    public void DesmontarPieza()
    {
        if (triggerDesmontajePieza == null ||
            !triggerDesmontajePieza.playerInRangePoint1)
            return;

        if (triggerDesmontajePieza.playerInRangePoint1)
        {
            if (piezaInstalada == null)
                return;

            PiezaMontaje1 pieza = piezaInstalada;
            pieza.transform.SetParent(null, true);

            Rigidbody rb =
                pieza.GetComponentInParent<Rigidbody>();

            if (rb != null)
            {
                rb.detectCollisions = true;
                rb.isKinematic = false;
                rb.useGravity = true;
            }

            pieza.estaMontada = false;
            piezaInstalada = null;
        }
    }
}

4.1. ¿Para qué sirve?

Es el controlador del punto de montaje. Detecta una pieza compatible que entra en su zona, conserva una referencia a ella y responde a la tecla G para instalarla. También conserva la referencia de la pieza instalada y permite desmontarla cuando el jugador está dentro de la zona de desmontaje.

4.2. Variables públicas

VariableTipoFunción
puntoAnclajeTransformTransform que define la posición y rotación exactas donde debe quedar la pieza instalada.
piezaDetectadaPiezaMontaje1Referencia a la pieza compatible que ha entrado en el Trigger de montaje y todavía no está instalada.
piezaInstaladaPiezaMontaje1Referencia a la pieza que actualmente ocupa el punto de montaje. Si vale null, el punto no tiene pieza registrada.
inTriggerboolIndica que una pieza compatible ha sido detectada por el Trigger de montaje. Se usa en la interfaz para mostrar el texto de montar cuando el jugador sostiene una pieza.
sistemaInteraccionSistemaInteraccionReferencia al controlador que gestiona la pieza agarrada. Después de montar, se llama a SoltarObjeto().
triggerDesmontajePiezaTriggerDesmontajePiezaReferencia al detector de proximidad del jugador. Su booleano autoriza o bloquea el desmontaje.

4.3. Detección de piezas: OnTriggerEnter y OnTriggerExit

OnTriggerEnter busca PiezaMontaje1 en el collider que entra o en sus padres. Si no encuentra el componente, ignora el objeto. Si la pieza ya está montada, también la ignora. En caso contrario, guarda la pieza en piezaDetectada y activa inTrigger.

OnTriggerExit busca de nuevo la pieza. Si la pieza que sale es la que estaba registrada como detectada y aún no está montada, limpia la referencia y desactiva inTrigger. La comparación piezaDetectada == pieza evita borrar la referencia por la salida de una pieza distinta.

Una sola pieza detectada: las variables guardan una única pieza. Si varias piezas compatibles entran simultáneamente, este diseño sencillo no mantiene una lista ni gestiona prioridades. Para el escenario de prueba con una sola esfera es suficiente.

4.4. Start() y referencias

La intención de Start() es obtener los componentes necesarios. Sin embargo, las dos líneas actuales llaman a GetComponent sobre las propias variables:

sistemaInteraccion =
    sistemaInteraccion.GetComponent<SistemaInteraccion>();

triggerDesmontajePieza =
    triggerDesmontajePieza.GetComponent<TriggerDesmontajePieza>();

Esto no busca los componentes en la escena. Solo busca un componente en el mismo GameObject que ya está referenciado por cada variable. Si la variable no se asignó previamente en el Inspector, será null y se producirá un NullReferenceException.

Por tanto, con este código las dos referencias deben estar asignadas en el Inspector antes de iniciar la escena. Una alternativa es buscar los componentes de forma explícita si no están asignados, por ejemplo con FindFirstObjectByType<SistemaInteraccion>(), pero esa búsqueda solo es apropiada si existe una única instancia relevante.

4.5. Update() y tecla G

En cada frame se comprueba si se acaba de pulsar G mediante Input.GetKeyDown(KeyCode.G). Si no se ha pulsado, el método termina inmediatamente.

Si se pulsa G:

  1. Si piezaInstalada no es null, intenta desmontarla llamando a DesmontarPieza().
  2. Si piezaDetectada no es null, llama a MontarPieza() y después a sistemaInteraccion.SoltarObjeto().
Orden y posible doble acción: son dos bloques if independientes. Si por alguna situación excepcional ambas referencias están asignadas al pulsar G, se intentarán ejecutar ambas operaciones en el mismo frame. Además, SoltarObjeto() se llama aunque MontarPieza() haya terminado anticipadamente por no tener puntoAnclaje. Una mejora sería hacer que el montaje comunique si tuvo éxito y soltar solo en ese caso.

4.6. Montaje: MontarPieza()

La secuencia de montaje es la siguiente:

  1. Validar el anclaje: si puntoAnclaje es null, el método termina sin montar.
  2. Guardar la pieza: copia piezaDetectada en una variable local para trabajar con la pieza seleccionada.
  3. Buscar el Rigidbody: busca un Rigidbody en la pieza o en sus padres. Es necesario para cambiar su comportamiento físico.
  4. Colocar y orientar: SetPositionAndRotation sitúa la pieza en la posición y rotación del anclaje.
  5. Detener el movimiento: pone linearVelocity y angularVelocity a cero para evitar que conserve velocidad lineal o giro.
  6. Hacerla cinemática: isKinematic = true hace que el Rigidbody deje de responder a fuerzas y simulación dinámica. useGravity = false desactiva la gravedad.
  7. Establecer la relación de jerarquía: SetParent(transform, true) convierte el objeto del punto de montaje en padre de la pieza, conservando su transformación mundial.
  8. Actualizar el estado: marca estaMontada = true, guarda la referencia en piezaInstalada y limpia piezaDetectada.

La pieza queda en el anclaje y registrada como instalada. El Rigidbody cinemático permite que permanezca fija sin que la gravedad la haga caer.

4.7. Desmontaje: DesmontarPieza()

  1. Comprueba que existe una referencia a triggerDesmontajePieza y que playerInRangePoint1 es true. Si no se cumple, termina sin desmontar.
  2. Comprueba que piezaInstalada contiene una pieza.
  3. Guarda la pieza en una variable local.
  4. SetParent(null, true) la separa de la estructura y conserva su posición y rotación en el mundo.
  5. Busca un Rigidbody y, si existe, activa las colisiones, desactiva el modo cinemático y reactiva la gravedad.
  6. Marca estaMontada = false y limpia piezaInstalada.
Detalle del Rigidbody: el código busca el Rigidbody con pieza.GetComponentInParent<Rigidbody>() después de separar la pieza con SetParent(null, true). Si el Rigidbody estaba en un padre anterior y no en el propio objeto de la pieza, puede dejar de encontrarse después de separarla. Es más robusto guardar la referencia al Rigidbody antes de cambiar el padre, o usar pieza.GetComponent<Rigidbody>() si el Rigidbody está siempre en el mismo GameObject que PiezaMontaje1.

5. Script 3 — SistemaInteraccion

Este es el controlador de interacción del jugador. Gestiona tres tareas relacionadas: detectar objetos bajo el centro de la cámara, sujetar y soltar un Rigidbody, y mostrar los mensajes de ayuda de la interfaz.

5.1. Raycast

VariableFunción
distanciaDeInteraccionDistancia máxima, en unidades de Unity, a la que el Raycast puede detectar un objeto. El valor inicial es 4.
capasParaRaycastMáscara de capas que limita qué colliders puede detectar el Raycast. Debe incluir la capa de las piezas interactuables.
camaraJugadorCámara desde la que se lanza el rayo. Si no se asigna, el script intenta usar Camera.main.

El rayo se construye con ViewportPointToRay(new Vector3(0.5f, 0.5f, 0)). Las coordenadas X e Y de 0.5 representan el centro de la vista de la cámara. Por eso el jugador apunta a un objeto colocándolo en el centro de la pantalla.

5.2. Interfaz

VariableCuándo se pretende mostrar
textoInteractuarCuando el Raycast encuentra un objeto con Rigidbody, tag Interactuable y pieza todavía no montada.
textoInteractuarSoltarCuando el jugador tiene un objeto agarrado y no está mostrando el mensaje de montaje.
montarTextCuando el jugador sostiene un objeto y montajeClass.inTrigger indica que la pieza está en el Trigger de montaje.
desmontarTextCuando el jugador está dentro del Trigger de desmontaje y existe una pieza instalada.

Los textos son referencias a componentes TextMeshProUGUI. El script no crea esos textos: espera que estén diseñados en un Canvas y asignados en el Inspector.

5.3. Sujeción

VariableFunción
puntoDeSujecionTransform hacia el que se atrae el objeto agarrado. Si no se asigna, se crea un objeto vacío como hijo de la cámara, a 2 unidades en su eje Z local.
velocidadAtraccionMultiplicador que convierte la distancia al punto de sujeción en una velocidad deseada. Valor inicial: 12.
velocidadMaximaLímite de magnitud de la velocidad aplicada al Rigidbody. Valor inicial: 10.
objetoAgarradoRigidbody actualmente sujeto. Si es null, el sistema considera que no hay objeto agarrado.

5.4. Referencia al montaje y variables privadas

montajeClass referencia al PuntoMontaje1 para consultar si la pieza está dentro del área de montaje y si hay una pieza instalada. Si no se asigna, Start() intenta encontrar uno mediante FindFirstObjectByType<PuntoMontaje1>().

detectCollisionsOriginal, dampingOriginal y angularDampingOriginal guardan valores físicos originales al recoger un objeto. En el código actual esos valores se guardan, pero no se restauran posteriormente. Por tanto, son variables preparadas para una restauración que todavía no está implementada.

5.5. Start()

Se ejecuta una vez al inicializar el componente. Sus tareas son:

  • Obtener la cámara principal si camaraJugador no fue asignada.
  • Desactivar este componente si no se encuentra ninguna cámara, ya que no podría lanzar el Raycast.
  • Buscar un PuntoMontaje1 si montajeClass está vacío.
  • Ocultar inicialmente todos los textos de interacción.
  • Crear PuntoDeSujecion como hijo de la cámara, si no se había asignado manualmente.

5.6. Métodos de interfaz

esconderTodosTextos() desactiva los cuatro objetos de texto si sus referencias no son null. Se llama al principio de cada Update(), por lo que la interfaz se reconstruye cada frame según el estado actual.

mostrarTexto(TextMeshProUGUI texto) activa el GameObject del texto recibido. esconderTexto(TextMeshProUGUI texto) lo desactiva. Ambos métodos comprueban que la referencia no sea null antes de acceder a ella.

5.7. Update(): prioridad de los mensajes

Primero se ocultan todos los textos. Después se evalúa el contexto actual.

A. Mensaje para desmontar

Se muestra desmontarText cuando se cumplen simultáneamente estas tres condiciones:

  • montajeClass existe.
  • montajeClass.triggerDesmontajePieza existe y su playerInRangePoint1 es true.
  • montajeClass.piezaInstalada no es null.

Esto significa que el jugador está en la zona autorizada y hay una pieza que se puede desmontar.

B. Cuando ya hay un objeto agarrado

Si objetoAgarrado != null, el script oculta los mensajes de interacción normal y muestra el de soltar. Si además montajeClass.inTrigger es true, muestra montarText y oculta el mensaje de soltar. Si no está dentro del Trigger de montaje, llama a esconderTodosTextos().

Al final de esta rama se usa return. Esto es importante: mientras el jugador sostiene un objeto, el método no continúa al Raycast de objetos nuevos. El jugador primero debe soltar o montar la pieza.

C. Cuando no hay un objeto agarrado

Se lanza el Raycast desde el centro de la cámara. Si encuentra un Rigidbody y su tag es Interactuable, el script comprueba si la pieza no está montada. Si no está montada, muestra textoInteractuar. Al pulsar F, llama a AgarrarObjeto(rb).

Suposición del código actual: después de encontrar el Rigidbody, se llama a GetComponentInParent<PiezaMontaje1>().estaMontada sin comprobar si el componente existe. Por ello, todo objeto con tag Interactuable que pueda detectar el Raycast debe tener PiezaMontaje1 en sí mismo o en uno de sus padres. Si no, puede producirse un NullReferenceException.

5.8. FixedUpdate(): movimiento hacia el punto de sujeción

FixedUpdate() se ejecuta en el ciclo de física de Unity. Si no hay objeto agarrado, termina. Si lo hay:

  1. Calcula la dirección desde el centro de masa del Rigidbody hasta el punto de sujeción.
  2. Multiplica esa dirección por velocidadAtraccion para obtener una velocidad deseada.
  3. Limita la magnitud de esa velocidad con Vector3.ClampMagnitude y velocidadMaxima.
  4. Asigna el resultado a rb.linearVelocity.

El resultado es una atracción basada en velocidad: el objeto se desplaza hacia el punto delante de la cámara. No se usa una articulación física ni se teletransporta el objeto cada frame. Las colisiones pueden influir en su recorrido.

5.9. AgarrarObjeto(Rigidbody rb)

Este método recibe el Rigidbody que el Raycast ha identificado. Oculta el texto de interacción, muestra el texto de soltar, guarda el Rigidbody en objetoAgarrado y almacena algunos valores físicos originales. Después aumenta linearDamping y angularDamping a 5 para amortiguar el movimiento y el giro mientras se transporta.

El método no desactiva la gravedad ni convierte el Rigidbody en cinemático. La atracción se realiza en FixedUpdate() asignando velocidad.

5.10. SoltarObjeto()

Si no hay objeto agarrado, no hace nada. En caso contrario, guarda localmente el Rigidbody, limpia objetoAgarrado, establece linearDamping = 0 y angularDamping = 0.05, y oculta todos los textos.

Al limpiar objetoAgarrado, FixedUpdate() deja de modificar su velocidad y el objeto vuelve a comportarse según su configuración física actual.

5.11. Otras partes

OnDisable() llama a SoltarObjeto() si el componente se desactiva mientras sostiene algo. Esto evita dejar el objeto registrado como agarrado por un sistema que ya no está activo.

La propiedad ObjetoAgarrado expone el Rigidbody actual mediante un getter de solo lectura. Otros scripts pueden consultar qué objeto se está sujetando, pero no pueden asignarlo directamente a través de esa propiedad.

6. Script 4 — PiezaMontaje1

using UnityEngine;

public class PiezaMontaje1 : MonoBehaviour
{
    public bool estaMontada = false;
}

Es el componente identificador más sencillo del sistema. Se añade a cada objeto que pueda instalarse en el punto de montaje.

ElementoSignificado
estaMontadaEstado de la pieza. false significa que no está instalada; true significa que el sistema la considera instalada.

El componente no mueve el objeto, no modifica su Rigidbody y no escucha entradas de teclado. Solo guarda el estado. Las operaciones reales las realizan PuntoMontaje1 y SistemaInteraccion.

Ventaja de separar responsabilidades: otros sistemas pueden preguntar estaMontada sin tener que conocer todos los detalles del montaje. Por ejemplo, el sistema de interacción evita recoger una pieza que ya está instalada.

7. Flujo completo de funcionamiento

7.1. Recoger una pieza

  1. El jugador apunta con el centro de la cámara a la pieza.
  2. El Raycast detecta un collider incluido en capasParaRaycast.
  3. El sistema busca un Rigidbody en el collider o sus padres.
  4. Comprueba que el Rigidbody tenga el tag Interactuable.
  5. Comprueba que exista PiezaMontaje1 y que estaMontada sea false.
  6. Al pulsar F, el Rigidbody se guarda en objetoAgarrado y se aplica amortiguación.
  7. En cada FixedUpdate, su velocidad se dirige hacia puntoDeSujecion.

7.2. Montar una pieza

  1. La pieza entra en el Trigger del objeto que contiene PuntoMontaje1.
  2. OnTriggerEnter encuentra PiezaMontaje1, comprueba que no esté instalada y guarda la referencia en piezaDetectada.
  3. inTrigger pasa a true.
  4. SistemaInteraccion detecta que hay un objeto agarrado y que inTrigger es verdadero; muestra el texto de montar.
  5. Al pulsar G, PuntoMontaje1.Update() llama a MontarPieza().
  6. La pieza se alinea con puntoAnclaje, se detiene, se hace cinemática y se convierte en hija del punto de montaje.
  7. Se marca estaMontada = true y se guarda como piezaInstalada.
  8. Se llama a SoltarObjeto() para que el sistema de interacción deje de atraerla.

7.3. Desmontar una pieza

  1. El jugador entra en el Trigger de desmontaje.
  2. TriggerDesmontajePieza encuentra PlayerTrigger en el collider o alguno de sus padres.
  3. El indicador playerInRangePoint1 pasa a true.
  4. SistemaInteraccion comprueba que el jugador está en rango y que piezaInstalada no es null; entonces muestra desmontarText.
  5. Al pulsar G, PuntoMontaje1 llama a DesmontarPieza().
  6. El método comprueba de nuevo que el jugador está en rango.
  7. La pieza se separa de la estructura, se vuelve dinámica y recupera la gravedad.
  8. Se marca estaMontada = false y se limpia piezaInstalada.
Nota sobre la tecla G: la misma tecla se usa para montar y desmontar. La acción que se intenta depende de las referencias que estén activas: piezaInstalada para desmontar y piezaDetectada para montar.

8. Configuración en Unity Inspector

8.1. Objeto con PuntoMontaje1

  • Asignar puntoAnclaje al Transform que representa la posición y orientación final de la pieza.
  • Asignar sistemaInteraccion al objeto que contiene el único SistemaInteraccion que controla al jugador.
  • Asignar triggerDesmontajePieza al objeto que contiene el script de zona de desmontaje.
  • El collider de detección de montaje debe tener Is Trigger activado.

8.2. Objeto del jugador

  • Añadir un único SistemaInteraccion al objeto que debe controlar la interacción.
  • Asignar camaraJugador o asegurarse de que la cámara tenga el tag MainCamera.
  • Asignar los cuatro textos TMP: interactuar, soltar, montar y desmontar.
  • Asignar montajeClass o permitir que el script encuentre el punto de montaje en la escena.
  • Asegurarse de que el jugador o uno de sus padres tenga PlayerTrigger.

8.3. Objeto de la pieza

  • Añadir PiezaMontaje1.
  • Añadir un Collider adecuado.
  • Añadir un Rigidbody, normalmente en el mismo objeto que la pieza.
  • Asignar el tag Interactuable.
  • Comprobar que la capa del collider esté incluida en capasParaRaycast.

8.4. Zona de desmontaje

  • Añadir un Collider y activar Is Trigger.
  • Añadir TriggerDesmontajePieza.
  • Colocar y dimensionar el volumen para que cubra el área desde la que se permite desmontar.

9. Física, Rigidbody y eventos Trigger

Los eventos OnTriggerEnter y OnTriggerExit no se producen solo por tener dos colliders en la escena. La configuración de física debe cumplir las reglas de Unity para eventos Trigger: uno de los colliders debe ser Trigger y al menos uno de los objetos implicados debe participar mediante un Rigidbody o el tipo de controlador físico correspondiente.

10. Observaciones y limitaciones del código proporcionado

Esta sección documenta el comportamiento real del código recibido, no una versión hipotética corregida. Son puntos importantes para mantenimiento y futuras ampliaciones.

10.1. Referencias en PuntoMontaje1.Start()

Las llamadas a GetComponent se realizan sobre referencias que deben existir previamente. Si los campos están vacíos en el Inspector, el script puede lanzar una excepción al iniciar. La asignación manual en el Inspector es válida; en ese caso, no hace falta volver a buscar el componente sobre la misma referencia.

10.2. Posible doble llamada a SoltarObjeto()

En la rama de objeto agarrado de SistemaInteraccion.Update(), el código contiene:

if (Input.GetKeyDown(KeyCode.F))
{
    PiezaMontaje1 pieza =
        objetoAgarrado.GetComponentInParent<PiezaMontaje1>();

    if (pieza == null || !pieza.estaMontada)
    {
        SoltarObjeto();
    }
    SoltarObjeto();
}

La segunda llamada es incondicional dentro de la pulsación de F. Por eso, incluso si la pieza está montada, se llama a SoltarObjeto(). Si la pieza no está montada, se llama dos veces, aunque la segunda llamada no hace nada porque la primera ya dejó objetoAgarrado en null. La condición interna queda, en la práctica, sin efecto sobre el resultado final de esa pulsación.

10.3. Comprobación de PiezaMontaje1 en el Raycast

El Raycast presupone que cualquier objeto con tag Interactuable tiene el componente PiezaMontaje1 en sí mismo o en un padre. Si se quiere permitir otros tipos de objetos interactuables, debe comprobarse si el componente existe antes de consultar estaMontada.

10.4. Variables físicas guardadas pero no restauradas

Al recoger se guardan detectCollisionsOriginal, dampingOriginal y angularDampingOriginal. Al soltar, sin embargo, se asignan valores fijos de damping. Los valores originales guardados no se utilizan. Esto puede ser intencional si todas las piezas deben recuperar esos valores fijos, pero no es una restauración exacta de su estado inicial.

10.5. Detección de varios colliders del jugador

TriggerDesmontajePieza usa un booleano simple. Si el jugador tiene varios colliders, la salida de uno puede poner el booleano a false aunque otro collider del mismo jugador permanezca dentro. Para resolverlo se necesita mantener un conjunto o contador de colliders que siguen dentro, asegurando que solo se desactive el permiso cuando ya no quede ninguno.

10.6. Varias piezas dentro del Trigger de montaje

piezaDetectada almacena una sola pieza. El diseño está orientado a un punto y una pieza cada vez. Si se introducen varias piezas o varios colliders por pieza, puede ser necesario gestionar referencias por pieza y evitar que un evento de salida borre un estado que corresponde a otra.

10.7. Import usings

using Unity.VisualScripting; en PuntoMontaje1 y using JetBrains.Annotations; en TriggerDesmontajePieza no se utilizan en el código mostrado. No afectan al comportamiento, pero pueden eliminarse si no se necesitan.

10.8. Textos: orden de prioridad

esconderTodosTextos() se ejecuta al principio de cada frame. Después se vuelven a mostrar los mensajes que correspondan. En la rama de objeto agarrado, si el jugador no está dentro del Trigger de montaje, se vuelven a ocultar todos los textos. Eso también oculta desmontarText, aunque se hubiera mostrado al principio del frame. Por tanto, si el jugador sostiene una pieza mientras está en la zona de desmontaje, la rama de objeto agarrado puede ocultar el mensaje de desmontar. La prioridad actual de la interfaz depende del orden de ejecución dentro de Update().

Recomendación de mantenimiento: antes de ampliar el sistema, conviene decidir explícitamente qué texto tiene prioridad cuando se cumplen varias condiciones (por ejemplo, jugador en zona de desmontaje y objeto agarrado). Después se puede centralizar esa decisión en un único bloque de interfaz.

Resumen final

El sistema se basa en estados y referencias compartidas. PiezaMontaje1.estaMontada indica si una pieza está instalada; PuntoMontaje1 controla la instalación y retirada; TriggerDesmontajePieza informa de la proximidad del jugador; y SistemaInteraccion se ocupa de recoger, transportar, soltar y mostrar la interfaz.

La tecla F se utiliza para recoger o soltar. La tecla G se utiliza para montar o desmontar. El montaje requiere que una pieza compatible haya entrado en el Trigger de montaje; el desmontaje requiere que exista una pieza instalada y que el jugador esté dentro del Trigger de desmontaje.

Documento elaborado a partir de los cuatro scripts facilitados. Las observaciones de la sección 10 describen limitaciones presentes en esos fragmentos y no implican que se hayan modificado los scripts.
